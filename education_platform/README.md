# Платформа онлайн-обучения (Education Platform API)

Бэкенд-сервис для платформы онлайн-образования, разработанный на FastAPI в строгом соответствии с принципами чистой архитектуры (Clean Architecture) и предметно-ориентированного проектирования (Domain-Driven Design, DDD). 

Платформа поддерживает иерархическое создание курсов, отслеживание прогресса студентов, интерактивные тесты, асинхронную проверку кода задач в изолированном воркере через очередь Redis, хранение медиафайлов в S3, многоуровневое кеширование в Redis с точечной инвалидацией, полиморфные комментарии и аналитику для авторов.

## Архитектура проекта

Приложение разделено на четыре изолированных слоя. Зависимости направлены строго внутрь (от внешних адаптеров к ядру предметной области):

1. **Слой домена (`app/domain`)**:
   - Содержит бизнес-сущности (`Course`, `Lecture`, `Task`, `CodeTask`, `User`, `Progress`, `Comment`, `CourseReview`, `StudentActivity`), объекты-значения (Value Objects) и доменные исключения.
   - Полностью изолирован от внешних фреймворков, баз данных и сторонних библиотек.

2. **Слой приложения (`app/application`)**:
   - Реализует сценарии использования (Use Cases), управляющие бизнес-логикой (жизненный цикл курсов, обработка сабмитов, создание отзывов).
   - Определяет интерфейсы (порты) для репозиториев, Unit of Work, файлового хранилища, кеша и очередей сообщений.
   - Применяет бизнес-правила и проверки прав доступа (например, запрет на оставление отзыва студентам с прогрессом ниже 80%).

3. **Слой инфраструктуры (`app/infrastructure`)**:
   - Реализует адаптеры к портам из слоя приложения:
     - **База данных**: асинхронный движок SQLAlchemy 2.0, декларативные модели, мапперы и паттерн Unit of Work.
     - **Кеш**: адаптер Redis для быстрого чтения каталога и структуры с автоматической инвалидацией при модификациях контента.
     - **Очередь сообщений**: реализация очереди на базе списков Redis для задач проверки кода.
     - **Хранилище файлов**: асинхронный клиент `aioboto3` для загрузки обложек в S3/MinIO.
     - **Безопасность**: генерация и верификация токенов JWT, хеширование паролей через `pwdlib` (bcrypt).

4. **Слой представления (`app/presentation`)**:
   - Роутеры FastAPI, обработчики запросов, внедрение зависимостей (`app/presentation/api/dependencies.py`), схемы Pydantic v2 для валидации входящих данных и сериализации ответов.

## Функциональные возможности

- **Управление курсами и контентом**:
  - Иерархическая структура: Курс -> Модули -> Секции -> Уроки (Лекции, Задачи с ручным вводом, Задачи с кодом).
  - Жизненный цикл курса: Черновик (Draft), Опубликован (Published), В архиве (Archived). Проверка готовности курса перед публикацией.
  - Загрузка обложек курсов в S3/MinIO с проверкой формата и размера файла.

- **Обучение и интерактивные задания**:
  - Тестовые вопросы с единичным и множественным выбором с автоматической проверкой и подсчетом попыток.
  - Задачи по программированию с набором тестов.
  - Асинхронное исполнение кода: решения помещаются в очередь Redis и исполняются независимым фоновым воркером.
  - Пошаговое отслеживание прогресса прохождения уроков студентами.

- **Каталог, поиск и кеширование**:
  - Публичный каталог курсов с полнотекстовым поиском, фильтрацией по тегам, сложности и статусу.
  - Высокопроизводительный слой кеширования (`RedisContentCache`) для каталога, карточек курсов и структуры.
  - Точечная инвалидация кеша при любых изменениях структуры курса или материалов уроков.

- **Сообщество и обратная связь**:
  - Полиморфные комментарии: обсуждения могут привязываться как к лекциям, так и к задачам, с контролем прав доступа.
  - Система отзывов и рейтингов курсов с ограничением (доступно только студентам, завершившим более 80% курса) и пересчетом средних оценок.

- **Аналитика и активность**:
  - Аналитика преподавания для авторов: выявление оттока студентов по секциям, проблемные задания, процент завершения.
  - Тепловая карта активности студентов и журнал активности для администраторов.

- **Аутентификация и авторизация (RBAC)**:
  - Авторизация по JWT-токенам (Bearer).
  - Ролевая модель доступа: `admin`, `author`, `student`.

## Технологический стек

- **Язык и среда**: Python 3.12+
- **Веб-фреймворк**: FastAPI, Starlette, Uvicorn
- **Валидация данных и конфигурация**: Pydantic v2, Pydantic Settings
- **База данных и ORM**: SQLAlchemy 2.0 (asyncio), aiosqlite (локально/тесты) / asyncpg (продакшн), Alembic
- **Кеширование и брокер задач**: Redis 7+
- **Объектное хранилище**: aioboto3 (AWS S3 / MinIO)
- **Безопасность**: PyJWT, pwdlib (bcrypt)
- **Тестирование и линтинг**: pytest, pytest-asyncio, httpx, Ruff

## Установка и запуск

### Предварительные требования

- Python версии 3.12 или выше
- Docker и Docker Compose (для запуска PostgreSQL, Redis и MinIO)
- Make (опционально, для запуска готовых команд)

### Переменные окружения

Создайте файл `.env` в корневой директории проекта на основе `.env.example`:

```bash
cp .env.example .env
```

Описание основных параметров:

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `APP_ENV` | Окружение запуска (`development`, `production`) | `development` |
| `APP_TITLE` | Название сервиса в Swagger документации | `FastAPI Education` |
| `APP_DEBUG` | Режим отладки | `true` |
| `API_PREFIX` | Базовый префикс всех маршрутов API | `/api` |
| `DATABASE_URL` | URL подключения SQLAlchemy (PostgreSQL или SQLite) | `postgresql+asyncpg://<user>:<password>@localhost:5432/<db>` |
| `DATABASE_ECHO` | Логирование SQL-запросов | `false` |
| `POSTGRES_USER` | Пользователь PostgreSQL для Docker | обязателен |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL для Docker | обязателен |
| `POSTGRES_DB` | Имя базы данных PostgreSQL для Docker | `education_db` |
| `POSTGRES_PORT` | Порт PostgreSQL на хосте | `5432` |
| `JWT_SECRET_KEY` | Секретный ключ для подписи JWT токенов | обязателен |
| `JWT_ALGORITHM` | Алгоритм шифрования JWT | `HS256` |
| `JWT_ACCESS_TOKEN_EXPIRE_MINUTES` | Срок жизни access токена в минутах | `30` |
| `REDIS_URL` | Адрес подключения к серверу Redis | `redis://localhost:6379/0` |
| `REDIS_PORT` | Порт Redis на хосте | `6379` |
| `SUBMISSION_QUEUE_NAME` | Имя очереди задач проверки кода в Redis | `code-submissions` |
| `CONTENT_CACHE_TTL_SECONDS` | Время жизни кеша каталога и курсов в секундах | `300` |
| `S3_ENDPOINT_URL` | Адрес S3 / MinIO сервера | `http://localhost:9000` |
| `S3_ACCESS_KEY` | Ключ доступа S3 / MinIO | обязателен |
| `S3_SECRET_KEY` | Секретный ключ S3 / MinIO | обязателен |
| `S3_BUCKET_NAME` | Имя бакета для хранения обложек курсов | `course-covers` |

### Пошаговый запуск

1. **Создание виртуального окружения и установка зависимостей:**

   ```bash
   make install
   # либо вручную:
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

2. **Запуск инфраструктуры в Docker (PostgreSQL, Redis, MinIO):**

   ```bash
   make compose-up
   # либо напрямую через docker:
   docker compose up -d
   ```

3. **Применение миграций базы данных:**

   ```bash
   make migrate
   # либо напрямую:
   alembic upgrade head
   ```

4. **Запуск сервера разработки:**

   ```bash
   make run
   # либо:
   uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
   ```

После запуска API доступен по адресу `http://127.0.0.1:8000`.

## Фоновый воркер проверки кода

Решения задач по программированию проверяются асинхронно отдельным процессом воркера. Для его запуска выполните:

```bash
make worker
# либо:
python -m app.run_code_submission_worker
```

Воркер непрерывно считывает поступившие решения из очереди Redis, запускает тесты, обновляет статус проверки в базе данных (`passed` / `failed`) и обновляет прогресс студента по курсу.

## Миграции базы данных

Управление схемой базы данных осуществляется через Alembic:

- **Создать новую автоматическую миграцию:**
  ```bash
  make migration m="название_миграции"
  # либо:
  alembic revision --autogenerate -m "название_миграции"
  ```

- **Применить все миграции:**
  ```bash
  make migrate
  # либо:
  alembic upgrade head
  ```

- **Откатить последнюю миграцию:**
  ```bash
  make migrate-down
  # либо:
  alembic downgrade -1
  ```

## Тестирование

Проект покрыт модульными, интеграционными и сквозными (E2E) тестами.

Запуск всего набора тестов:

```bash
pytest
```

Запуск отдельных групп тестов:

```bash
# Модульные тесты
pytest tests/unit

# Интеграционные тесты API и базы данных
pytest tests/integration

# Конкретный тестовый файл
pytest tests/integration/api/test_course_lifecycle_api.py
```
